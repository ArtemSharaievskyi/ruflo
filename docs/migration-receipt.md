# Migration verification, 2026-10-09

- NEUSTAND retained its original Git repository, HEAD `0c8e4682e555be0c2299b1615b3114f20b33e606`, and `origin`. Its existing three modified application files and untracked Hero image were hash-checked against the pre-migration backup after the work.
- The factory is a separate uncommitted Git repository with no remote. It holds 14 agent profiles with preserved original sources and license, 28 shared skill directories, source locks, a neutral tool map, and site scripts. The NEUSTAND-specific frontend skill and design decisions remain at the site.
- A blank test site was created with a distinct UUID, its own Git repository without a remote, an empty brief, and a separate initialized Ruflo database. It contained no NEUSTAND application assets. The test sites were archived outside both repositories after verification.
- Ruflo 3.54.1 MCP `memory_search` and `memory_retrieve` were called against two site databases. A synthetic NEUSTAND key was found in NEUSTAND and returned `found: false` in the second site; the synthetic key was then deleted from NEUSTAND. `CLAUDE_FLOW_MEMORY_PATH` is required for MCP search in this installed version in addition to `CLAUDE_FLOW_DB_PATH`. The launcher sets both, fixes MCP's working directory to the site, and allows only five basic memory tools; Codex `mcp get ruflo` confirmed that effective configuration.
- A fresh Codex session in the empty site saw the shared DaisyUI and security-audit skills; a read-only Frontend Developer custom agent invocation returned its role name. The factory's agent and skill paths were checked against its map.
- An isolated NEUSTAND copy without factory links or local `.env` passed `npm ci`, `npm run typecheck`, `npm run lint`, `npm run build`, and all 22 desktop/mobile Playwright tests with the local Resend simulation. A separate production browser check returned HTTP 200 on both viewports, loaded the Hero, and fetched 9/9 desktop and 10/10 mobile image URLs.
- Lighthouse CI completed collection but failed five recommended assertions: forced reflow, legacy JavaScript insight, network dependency tree insight, unused JavaScript, and responsive images. Its existing server command was corrected so the check could run. The application code and assets were unchanged by this migration.
- OSV was not rerun because the scanner sends dependency information to an external service. The site's prior local scan is recorded in `docs/SECURITY.md`; the migrated lockfile still has the documented development-only `extract-zip@2.0.1` and `sprintf-js@1.0.3` chains, and neither is in the production dependency tree.

Codex's own global session history remains under the user's Codex home; the launch script starts fresh sessions but cannot physically isolate that history without separate authentication homes. Ruflo's other optional subsystems were not claimed as isolated or enabled. Interactive Codex could not be launched in the verification terminal because it reports `TERM=dumb`; the launcher specifies `-a on-request -s workspace-write`, and the site's ignored config contains the same settings. A noninteractive `codex exec` probe reported effective approval `never`, so that mode was not added to the launcher. No Git staging, commit, push, merge, or publication was performed.
